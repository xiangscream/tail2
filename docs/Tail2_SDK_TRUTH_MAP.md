This map answers, per capability: what it is, whether Tail2 supports it, in what
state, its input range, what it actually does, whether it can be read back, its
visual effect, hidden side effects, failure mode, recovery and primitive value.

## 0. Status vocabulary

| status | meaning |
|---|---|
| `VERIFIED` | physical / visual / state behavior reproduced on Tail2 |
| `READBACK_VERIFIED` | getter / status path proven; no write behavior implied |
| `ACCEPTED_UNPROVEN` | SDK accepted the request; physical / visual result not proven |
| `CONSTRAINED` | works only under documented runtime conditions |
| `UNSUPPORTED_TAIL2` | declared elsewhere but not usable on Tail2 |
| `NO_PUBLIC_PATH` | enum / hint exists but no complete public API contract |
| `DEFERRED_UNSAFE` | relevant but destructive or unsafe to exercise automatically |
| `NOT_PRODUCT_RELEVANT` | present in SDK but irrelevant to the Agent Camera MVP |
| `PENDING_WAVE_A` | **pre-device placeholder**: static census done, dynamic truth not yet measured (device was off during Phase 0). Must be resolved before the map freezes. |

Evidence levels: `static` (declaration / doc only) · `rc` (return code) ·
`readback` (typed getter) · `physical` (device motion / LED) · `visual` (frame
change) · `artifact` (file / media). `rc=0` never upgrades a row above
`ACCEPTED_UNPROVEN`.

Two standing cautions established during M0/M1B:

1. **Doc applicability is a hint, not truth.** `gimbalSpeedCtrlR` /
   `gimbalGetAttitudeInfoR` are documented `tailair+tiny` yet are proven working
   on Tail2; conversely `cameraGetZoomAbsoluteR` omits Tail2 in its doc but its
   readback worked. Every Wave A row therefore needs a device verdict.
2. **No write without readback.** Several Tail2 setters return `rc=0` and do
   nothing (silent no-op). Evidence must include a getter and/or a frame.

## 5. What Wave A must still answer

1. Is there a Tail2-reliable **absolute look** (angles), and does it suspend AI tracking?
2. Units / sign / axis order / range for angle and speed paths, and whether limits
   and reverse can be **read back** (`aiGetGimbalParaR`).
3. Is native stop more reliable than legacy zero-speed, and what is the recovery
   path after manual control (LED / stuck-state transitions must be recorded)?
4. Which of the 24 AI control parameters are actually writable on Tail2, and do
   Offset/AutoZoom/Composition require a documented precondition (Track submode,
   `GimCtrlMode=PRO`, `TrackerType=LimitArea`)?
5. Do `DevTargetViewType` / `DevTargetZoomType` produce measurable framing change,
   and what side effects do they have on target selection?
6. Zoom: relative / stop / auto-zoom / digital-zoom paths, plus readback latency
   and asynchronous completion semantics.
