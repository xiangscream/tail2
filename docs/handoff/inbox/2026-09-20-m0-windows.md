## 2. 构建与离线测试

```powershell

python -m unittest discover -s tests -v
```

结果：`tail2_probe.exe` Release x64 构建成功；**29 项测试全部通过**（23 Python + 6 native 协议测试）。6 个 native 测试此前在 Linux 上因无编译产物而 skip，本次真实运行。

一处代码修复（随本分支提交）：

- `native/CMakeLists.txt`：`target_compile_definitions(... BOOST_JSON_NO_LIB BOOST_CONTAINER_NO_LIB)`。
- 原因：Boost.JSON 经 `boost/container/pmr/memory_resource.hpp` 触发 Boost.Container 自动链接，原工程只定义了 `BOOST_JSON_NO_LIB`，MSVC 链接报 `LNK1104 libboost_container-vc143-mt-x64-1_88.lib`。补 `BOOST_CONTAINER_NO_LIB` 后 header-only 链接通过，无需引入 Boost 编译库。

## 3. 只读枚举与设备绑定

`device.list` 回读（本地）：`product_type=11`(Tail2)、`transport=0`(`DevModeUvc`)、`eligible=true`、`firmware=7.2.9.41`、`video_name=OBSBOT Tail 2 Camera`。

UVC 索引绑定：Windows DirectShow 枚举顺序为 `0=Integrated Camera, 1=OBSBOT Tail 2 Camera, 2=OBSBOT Virtual Camera, 3=OBS Virtual Camera`。SDK `video_name` 与 DirectShow 索引 1 的名称一致，据此绑定 **UVC index=1**。单帧观察：`snapshot --index 1 --backend dshow` 成功，`640x480`，`device_binding=UNVERIFIED`（工具默认值）。物理绑定由 §4 的运动在画面外目视确认（相机可见被摄者，转动被观察到）。

失败/不稳定：`device.list` 检测不稳定——自动 3s 等待曾返回空列表导致 `device.open` 失败（失败 2 次）；用 5s/8s 等待后稳定成功。建议 M1 之前不要假设固定等待即就绪。

## 4. 停止路径与小范围控制（人在现场）

先证明停止，再运动。全部在 `--allow-control --allow-legacy-probes` 下：

| 步骤 | SDK 调用 | rc | 设备/回读 |
|---|---|---|---|
| look.stop | `aiSetEnabledR(false)` + `gimbalSpeedCtrlR(0,0,0)` | 0 / 0 | accepted |
| track.set(false) | `aiSetEnabledR` | 0 | accepted |
| look.status | `gimbalGetAttitudeInfoR` | 0 | roll≈0.3°, pitch=0°, yaw≈-6.4° |
| look.nudge(1dps,100ms) | `aiSetEnabledR(false)`+`gimbalSpeedCtrlR(pitch,pan,0)`+`(0,0,0)` | 全 0 | yaw 变化 ≈ +0.05° |
| look.nudge(5dps,200ms) | 同上 | 全 0 | yaw 变化 ≈ +0.87° |
| look.nudge(10dps,500ms)×2 | 同上 | 全 0 | yaw −5.43°→−1.28°→+3.22°，合计 ≈ +9.0° |
| look.stop（其后） | 同上 | 全 0 | yaw 停 +3.62°（残余 ≈ +0.4°） |

结论：
- `gimbalSpeedCtrlR` 形参为 `(pitch, pan, roll)`；**文档类别未列 Tail2**（tiny/tiny2/tail air），但本机固件 `7.2.9.41` 实测有效。
- 方向：**pan 正 → yaw 正**。
- 停止：`look.stop` 后位置保持，残余约 0.4°（回读时刻/coasting，未判定为失控）。
- 操作者目视确认：约 10° 转动并停住。
- 不稳定：legacy `gimbalGetAttitudeInfoR` 间歇失败（1 次 `rc=-1`，耗时 2017ms；其余 6 次 rc=0）。

## 5. 媒体兼容矩阵（UVC vs 机内 Capture/Record）

保持 UVC，未切换输出模式。

| 操作 | SDK 调用 | rc | 类型化回读 |
|---|---|---|---|
| capture.device | `cameraSetMediaOperateParamR(Capture,Start)` | 0 | capture getter `rc=-1`（读不到） |
| record.start | `cameraSetMediaOperateParamR(Record,Start)` | 0 | `record_operation_raw=2`(Stop) |
| record.stop | `cameraSetMediaOperateParamR(Record,Stop)` | 0 | `record_operation_raw=2`(Stop) |

- **setter 全部返回 rc=0，但 record 回读始终 Stop，capture 回读直接失败。**
- 现场无 SD 卡，无法产生/取回机内文件，因此**不能**用文件产物判定互斥。
- 手册 v1.0 与操作者均确认 UVC 下机内录像不可用；本报告把该结论记为“手册+操作者确认”，**文件级验证保持 indeterminate**。
- SDK 未编码互斥关系；`setDevEventNotifyCallbackFunc` 注释为 “only for tail air”，`startFileDownloadAsync` 注释为 meet/tiny2 series，Tail2 机内文件取回路径在 SDK 中未见明确文档。
- 建议：向产品负责人提出 `host_uvc` 媒体 Provider（USB 快照属观察文件，不得计作机内照片）；确认前不静默更换。

## 7. 手动干预与失败统计

- 操作者把设备 USB 模式从 **MTP**（transport=2，WPD 类，无 UVC）切到 **UVC**，并重新插拔线缆；切换前 `eligible=false`，切换后 `transport=0`、`eligible=true`。
- OBSBOT Center / OBSBOT_Main 曾运行并独占 Tail2 UVC，导致 index 1 打不开；操作者退出后恢复。**违反单写者约束**，后续测试期间须关闭。
- VS 安装：winget 首次安装只注册了 bootstrapper，留下 `state.json` 标记“已安装”但目录为空的**幽灵实例**，导致后续安装器判定无需安装。清除该实例后重新安装 VCTools 成功。
- 失败次数：`device.list` 空列表 2；`device.open` 因空列表失败 2；`gimbalGetAttitudeInfoR` rc=-1 1；快照因 Center 占用失败 1。
- 原始日志与观察文件路径（本地）：`.local/`（含 `run-py-*` trace、`observations/`），不入库。
