# Tail2 具身 Agent MVP：开发总计划

2026-09-20 · 本文件定义开发目标与阶段，不宣告尚未通过的设备能力。

## 1. 要交付的产品实验

让一个能看见现场的 Agent，通过少量产品级能力完成目标选择、跟踪、构图、视线调整与媒体任务，并能根据真实反馈继续、修正或结束。用户输入可先用命令行文字；观察与行动必须形成闭环。

第一个代表任务是：“跟画面左边穿黑衣的人，把他拍成全身。”成功时应能看到 Agent 用过哪张图、选中了哪个候选、调用了哪些能力、它们落到了哪些 SDK 调用，以及新画面是否满足意图。拍照和录像随后接上明确的媒体结果来源。

本项目交付四项资产：能力契约、设备适配器、视觉 Agent 闭环、观察状态页。官方模式和社区应用未来可以共享这些能力；当前无需开发应用运行平台。

## 2. 范围与成功标准

**必须做到**：选择多个对象中的具体对象；Agent 接收图像；USB/UVC 观察；Tracking / Framing / Look 的受控切换；明确 Capture / Record 来源；云台预置；分开的停止语义；设备状态与调用链可追溯。

**当前不做**：产品控制 UI、应用商店、社区分发、Development Agent、复杂人格和记忆、自动成片、云端任务服务、多 Agent。文本指令优先，语音输入可后加。Tail2 固件已经承担的跟踪和云台闭环直接复用，不在 PC 重造。

MVP 完成时，Agent 只能看见正式能力接口；每个代表任务至少组合多个能力；同样的能力能通过无模型脚本运行。日志能够区分模型选错人、坐标映射错误、设备拒绝、状态滞后和画面不满足要求。

本轮仅交付 M0 代码与离线验证。视觉模型、完整中层调度与实时观察循环进入 M1/M2。M0 真机通过由本地 Agent 的记录决定。

## 3. 架构与执行位置

```text
用户目标（CLI 文字）
        ↓
Runtime Agent：看图、语义选人、组织任务、检查结果
        ↕ 产品级能力请求 / 状态与结果
Capability Runtime：参数、依赖、控制权、时效、证据、取消
        ↕ 明确 SDK 调用 / 类型化回读
C++ libdev 适配器 → Tail2 固件跟踪、变焦、云台、媒体执行

Tail2 USB/UVC → 本地观察服务 → 图像 + 候选框 → Agent
控制、观察、媒体各有来源；只读状态页消费事件，不控制设备。
```

高层按任务事件更新。Tail2 固件持有实时跟踪与云台执行。PC 中层在能力需要时更新目标和约束，有限动作也可以事件驱动；不为追求“中频”机械地轮询所有 SDK 函数。

当前 native 桥按一条请求一条响应运行，是工程探针。M1 用有所有权与状态管理的能力层封住它。模型不会直接操作 probe JSONL，也不会接触任意 shell、文件路径或 SDK 函数名。

实施采用 Python 3.11+、C++17、私有 libdev、Boost.JSON 头文件、可选 OpenCV。Python/C++ 用 JSONL 子进程 IPC，避免过早引入 RPC 平台；stdout 只输出协议，SDK 日志写本地 stderr。只读状态页使用标准库 HTTP server、原生 HTML/JS 与 localhost 随机端口。

## 4. 观察和具体目标选择

### 4.1 候选提供者

优先 Native：设备输出当前画面中的候选列表，Agent 根据图像和列表选择一个候选。SDK 当前只找到 AI target 通知枚举，尚未找到候选列表读取路径；此结论保持 UNKNOWN。

其次 Host Detector：从同一 UVC 帧输出候选，Agent 做语义选择，再把选定区域交给设备跟踪。M0 附带 OpenCV HOG 人体检测作为无需另下载权重的台架基线，只覆盖人物初步试验，准确率不作承诺。若场景效果不足，M1 另评估本地检测模型的效果、许可证、算力与离线部署。

最后 Agent Box：多模态模型直接给框，作为显式后备路径。结果必须经过同样的合法性、时效和坐标校验。

原生候选调查限定在公开声明、样例和有文档的供应商答复；不解析未知二进制 payload。找不到入口即可报告并推进 Host Detector，避免阻塞整个项目。

### 4.2 图像和框必须属于同一时刻

一次 Observation 包含图像引用、observation_id、stream_session、camera_epoch、尺寸、方向/裁切、主机收帧时刻、可用的传感器时间以及候选来源。候选 ID 仅在该次观察内有效，不等于跨帧身份 ID。

UVC 索引必须与 SDK 控制的序列号做本地绑定。镜像、竖屏、裁切、变焦和云台移动都可能改变坐标关系；先校准 UVC 像素到 SDK ROI。Agent 看图期间发生视角或主体变化时，重新观察并重新关联，禁止沿用旧框点击。主机收帧时间只表示到达时间，不能自行证明相机曝光时刻或驱动缓冲的新鲜度。

M0 几何校验是契约测试，不包含完整跨帧目标关联。原始选框测试由操作者监督，目标先保持相对静止。M1 的选择入口才持有 Observation Store 与候选引用，统一完成下发前检查。

### 4.3 Agent 何时看

任务开始、选人之前、构图变化后、拍摄前、异常时和需要视觉条件判断时看图；长任务可增加慢速观察。常见任务使用持续的本地采集服务和最新帧缓存，避免每次打开 UVC 导致等待。M0 单次工具只验证采集是否通。

拍照后验证应读取本次实际图片文件。新的预览图只描述当前画面，不能充当刚才成片的验证依据。

## 5. 能力契约的必要约束

完整接口草案见 CAPABILITY_CONTRACT.md。这里保留会决定架构的几项：

- Target 指一个具体目标，类别 human 只帮助选择策略。SDK 选框可能同时改变自动跟踪与变焦；这类副作用必须探测并写回状态。
- Track 表示持续跟踪状态；“开始跟踪请求完成”与“跟踪会话结束”分别记录。
- Framing 保存构图意图。SDK 报告 full_body 配置后，视觉检查才判断头脚是否入画。画幅受安装位置、距离和视场限制，无法满足时返回具体受限原因。
- Manual Look 获得视线控制前暂停 Tracking；重新跟踪由明确命令恢复。M0 只提供有限小幅移动探针，方向、单位和停下效果需实测。
- Position 在 Tail2 上是云台视角预置。保存前确认 ID 归属和无覆盖策略，召回先处理 Tracking 控制权。向其他设备迁移时通过能力描述声明可用自由度，不假定相同语义已自动实现。
- Capture / Record 返回来源、操作状态、实际媒体 ID/路径和可取回状态。设备接受命令、进入工作状态、文件写完、用户可读取分别表示。
- task.cancel 停止当前编排并阻止排队后续动作；look.stop、track.stop、record.stop 分别处理各自工作。device.stop_all 清空任务并发送对应停止请求，只有设备确认后才能报告确认停下。传输超时保持 indeterminate，不自动重试具有副作用的动作。

**来源选择的新限制。** Tail2 用户手册 v1.0 的 Output 段写明 UVC 启用后机内录像不可用。保留 USB 观察主线，并用当前固件核实。若仍冲突，M1 可提议把 Capture / Record 的 MVP Provider 明确设为 PC-UVC 保存；用户确认后再实现，结果始终标为 host_uvc。需要验证机内录像能力时另做获准的非 UVC 试验。USB 画面截帧不直接称为机内拍照。

## 6. 可观察性与状态页

最小页面显示当前阶段、Agent 是否连接、请求、能力、SDK 调用名/返回码/耗时、类型化设备回读和错误。M0 只读页已实现上述探针可得信息，所有真机状态保持 pending 或原始值。

M2 加入本次 Agent 观察图、选中框、简短决策说明、能力级时序和结果图片。只展示可解释的决策摘要与输入证据，不要求模型提供隐藏推理。Requested、SDK reported、visually verified 分开展示，未知用 unknown，不用默认 false 冒充测量。

事件携带 run_id、request/task_id、observation_id、wall time 与 monotonic time。原始日志可包含设备信息，仅本地保存。状态页无控制接口、无任意文件服务；端口自动选择，禁止通过杀无关进程腾端口。

## 7. 里程碑与交付门槛

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| M0 工具 | 可编译桥、UVC 快照、候选探测、只读 trace、SDK 核对与台架手册 | 离线测试通过；真机未测项标清 |
| M0 真机 | Windows 构建；同设备 USB 控制与图像；ROI 映射；状态与停止；媒体模式矩阵 | 得到可重复探测记录；选框和停止路径已确认；其余能力逐项 available / unavailable / unknown |
| M1 中层 | 单写者调度、Observation Store、候选 Provider、Target/Track/Framing/Look、媒体与预置适配、取消与结果 | 无模型脚本完成选人→跟踪→构图→观察；副作用和未知状态不被隐藏；媒体 Provider 已确认 |
| M2 视觉 Agent | 多模态模型适配器、有限工具集、观察→行动→验证循环、图像与简短决策状态页 | Agent 能用同一契约完成多步任务，失败可定位；本地停止不等待模型返回 |
| M2 任务评测 | 固定任务集、重述测试、受控失败、实际素材验证 | 达到下述内部验收建议，由产品负责人确认后冻结 |

M0 先读与观察，再测试停止，再打开写入；Capture/Record/预置分支可以独立受阻，但不可偷偷标为已支持。M1 可以先做已验证能力子集，最终 MVP 仍需对目标能力逐项交代落实或不可用原因。

## 8. 验证任务与判据

内部建议以两名同意参与的成年人、固定机位和明亮室内开始。以下次数是项目验收建议，不是产品性能规格：

1. **目标选择**：“跟左边的人”“跟穿黑衣的人”。每种描述做多次位置交换，总计至少 10 次；身份错误必须显式失败或重选，不能将错误目标计为完成。
2. **构图闭环**：选中目标→全身→半身；检查所用图像、配置回读和实际构图。人在视场外、距离过近时能报告受限。
3. **控制权**：跟踪中“停跟，向左看一点”，随后恢复跟踪；至少 5 次反复，记录停止/切换是否真实生效。
4. **媒体结果**：实际照片或视频能从被声明的 Provider 取回、打开；拍后验证引用本次文件；前后两张素材不得混淆。
5. **视觉条件**：“保持举手直到开始录像”，以可持续被低频观察到的动作先验证。瞬间挥手属于另一项事件采集能力，不纳入首个低频快照承诺。
6. **复位与中止**：回到保存的云台视角；在多步任务中取消，后续命令不得继续下发。未知设备状态时不能显示完成。

记录每项请求的成败、重试、选人/构图耗时、人工干预和模型调用量；先用真实结果确定下一阶段时间预算。模型生成计划的复杂度不作为通过标准。

## 9. 并行工作与协作

网页端维护目标、契约、代码审查与计划；本地 Agent 负责 Windows、SDK ABI、USB、设备固件、真实画面与台架复现。正式判断来自可追溯运行结果，不来自某次聊天里的推断。

同仓库 `docs/handoff/CURRENT.md` 指向当前基线和任务。每轮本地工作从明确 commit 新建分支，记录命令、环境、结果和差异，通过 PR/issue 回报。原始图像和日志不公开。结果稳定后更新 SDK_FINDINGS 与正式代码，handoff 只保留下一步与尚未解决的问题。

前期不建立额外协调服务、自动轮询机器人或另一套任务数据库。

## 10. 尚需现场回答的五件事

- 原生候选是否有正式 payload 与订阅路径；选框与自动 Tracking 的真实副作用是什么？
- SDK 选框坐标与 UVC 输出是否一致；设备与视频索引能否稳定绑定？
- 旧类别接口在 Tail2 的 Tracking、Look、Preset 上是否生效，哪些回读能证明效果？
- 当前固件的 UVC / 机内 Capture / Record 是否互斥；媒体文件如何取得？
- 状态回调时效与物理停止行为能否支撑受监督的中层任务？

这些问题由 M0 回答。模型选型与云端图像授权在 M2 开始前确认；没有凭据也能完成 M0/M1 的本地工作。
